# 个人站点：调研与设计提案

## 定位

建议定位：系统技术创作者 × 独立开发者。

首页主张：**把复杂系统讲清楚，把想法做成工具。**

这是根据现有作品提出的编辑定位，公众号名称已确认为「王小二的技术栈」，草案暂用作站点品牌。个人姓名、职业、履历与其他联系方式尚未确认。

## 核心判断

现有作品最突出的共同点，是把系统机制转化为可以操作的学习过程。个人站应让访客先理解这种创作方法，再进入具体作品。独立 App 展示另一面：把技术用于生活中的具体需求。

站点承担内容总入口与策展功能。第一版保留作品独立部署，点击进入原站；暂不将大型交互作品 iframe 嵌入首页，避免加载成本与移动端操作冲突。

## 信息架构

导航：作品 / 写作与视频 / 关于。

1. 首屏：姓名或昵称（待确认）、一句创作主张、两句介绍、“探索作品”和“阅读与视频”入口。右侧以小型轨道示意呼应 Frame Lab，明确它是视觉示意，不充当真实仿真。
2. 交互实验：Frame Lab 大卡片，BinderABC 与 RPC 并列，dumpsys 以紧凑工具条展示。每项交代“解决什么问题”和“进入后能做什么”。
3. 独立应用：先用大卡展示 Toucharium 的开源移动系统实验，并标明开发预览状态；长截图助手、抗炎生活记录并列，真实图标及截图、用途、一键进入产品站。
4. 写作与视频：第一版使用掘金、简书、B 站入口，并展示「王小二的技术栈」微信公众号二维码。二维码使用用户提供的原图，保留白边，不裁切、不叠加装饰；桌面支持扫码，手机支持查看原图、保存后在微信识别。核实具体内容后，替换为 3–5 篇精选文章与 1–2 个视频，跨平台相同内容合并展示，并注明发布平台。
5. 关于：用简短段落讲关注的问题、创作方法与联系渠道。未确认前不写公司、年限、头衔、邮箱或 GitHub 地址。

后续有更多内容时，再拆分 /projects、/writing 和 /about；不为稀少内容预建空页面。

## 视觉方案

推荐“工程师的个人工作室”：暖白背景 #F7F6F2，墨色 #202822，强调蓝 #315FDC，细分隔线 #DCDDD5。项目示意区域用浅灰绿，独立 App 可保留原品牌色。

正文使用系统中文无衬线字体，英文编号与轨道标签使用等宽字体。桌面内容最大宽度约 1160px，首屏主标题约 64–76px，正文 16–18px；手机主标题约 38px，单列排列。中文承担主要信息，英文只用于项目名和少量编号。

以大字号、留白、细线和少量非对称布局建立层次。卡片内部以轨道、源码目录、通信线路和真实截图区分作品，避免六张同质缩略图。首页不使用粉丝数据、技能百分比、虚构更新动态或身份徽章。

动效仅用于链接反馈和轻微 hover；尊重减少动态效果设置。所有项目可通过键盘访问；小屏不依赖悬停和横向拖动。项目链接文本明确去向。

## 草案与落地顺序

同目录的 `首页草案.html` 是可直接打开的响应式排版概念稿，含真实外链；它不是正式上线实现，轨道是静态示意，品牌使用「王小二的技术栈」，不包含未核实的文章内容。

正式版本先补充简短自我介绍和希望公开的联系渠道，再挑选代表文章及视频。随后替换概念图为真实作品截图，完成桌面/手机视觉验收和链接检查。第一版可使用静态生成，内容用本地数据维护，无需先建设 CMS 或依赖平台实时抓取。

## 中英文支持

首页提供中文 / EN 切换，默认中文；记住手动选择的语言。导航、项目介绍、平台名称、公众号说明、图片替代文字和页面标题同步翻译，项目品牌名与原始外链保持一致。英文品牌译名暂用 Wang Xiaoer’s Tech Stack，公众号二维码保持原图。JavaScript 不可用时仍能阅读中文。

公众号展示：首屏不展示关注入口或二维码，仅保留页面后部的公众号区域，二维码尺寸为桌面 172px、手机 200px，保留完整白边和比例。
